主題：化學鍵結與分子結構。簡報：../slides/index.html。

目前狀態（如實）：Wiki 目前有 6 份來源（6 個章節／小節檔，出自 2 本書）：以使用者提供的 Zumdahl 10e 為主（第 4 章 §4.9、第 8、9、10 章，共 4 份），另以 OpenStax Chemistry 2e 的 §7.5、§8.4（網頁，2 份）作跨來源對照。Lint 已跑一次（56 頁），唯一回報的是 index 開頭說明文字裡的範例連結「頁名」，不是真的壞連結。下面的反思是根據實際紀錄寫的，不是預先編的。

Step 3　Loop／Graph

問題回答
哪些步驟會重複？③④⑤ 這個小圈：檢查不通過就退回重寫，直到通過。另一個大圈是「缺資料 → 回 Ingest → 重新查詢」，這一圈代價高，所以只在檢查列出缺資料時才走。
在哪裡檢查？⑤（內容）與 ⑦（畫面）。內容檢查放在生成 HTML 之前，因為在草稿階段改一句話很便宜，HTML 生成後再改要重跑整個頁面。
在哪裡重新生成？⑤ 不過 → 重寫 ③④；⑦ 不過 → 只重做 ⑥。
為什麼？簡報只准用 Wiki，所以「Wiki 沒有的東西」不能在生成時補，要回到 Ingest。這條規則讓每個錯誤能追到「是 Wiki 錯」還是「簡報寫錯」。

Step 4　反思（根據本輪實際紀錄）

1. 哪個節點最容易出錯？

最容易錯的是Ingest 的讀取與抄寫，不是 Query。實際紀錄：pdftotext 把負號、上標、等號弄壞（數值類全部要看圖片重核）；引用頁碼 p.42 實為 p.41；章節 §8.11 實為 §8.12；術語不一致 3 處。Ingest 後半段（第 9、10 章）又出現：圖號打錯（圖 8.24 實為 9.24）、一段範例裡寫了自我更正的文字、把「各族第一個元素」誤讀成「第一週期」、兩處術語重複（plane／planar、三角錐）。Query 兩輪（21 頁、31 頁）的自動檢查都是 0 失敗，是因為 Wiki 在 Ingest 階段已經被核對過。

2. 把哪個檢查提早？

兩次：(a) v3：數值在讀取當下用頁面圖片核對，而不是等寫完；(b) v4：連結、9 個欄位、術語、引用，改成每次寫入後自動跑，不等最後 Lint。Query 階段（v5）又加入數字比對、原文字串比對與渲染後看圖。

3. 有沒有修改流程或 graph？

有，CLAUDE.md 從 v1 改到 v5，每次的原因都記在第 12 節 changelog。v5 的觸發原因：簡報有 100 條論點（第二輪擴到 31 頁、170 條），人工對照容易漏；另外，晶格能兩本書符號相反，原本的規則是「不一致就降為低信心」，但這是「定義方向不同」而不是事實衝突，所以我在頁面、log、CLAUDE.md 都註明例外並保留信心程度；而 H₂ 曲線的標籤壓在曲線上，是文字檢查完全看不到的，截圖才發現。

4. 這個檢查本身的弱點（誠實）

原文字串檢查是我自己寫論點、自己挑字串，有「自己改自己考卷」的問題；Query 第一次就 0 失敗不代表內容完全正確。我用不存在的字串測過檢查器會失敗，但它抓不到「字串存在、卻用在錯的地方」。比較可靠的做法是讓另一個沒看過生產過程的檢查者抽查。

  • 簡報沒有涵蓋液態、蒸氣壓、相圖、陶瓷、X 射線繞射（Wiki 沒有）。
